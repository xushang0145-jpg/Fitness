# FitApp 项目章程

> 本文件是所有开发决策的最高准则。任何规格（spec）、方案（plan）、任务（tasks）与本章程冲突时，以本章程为准；确需违反时，必须先修订章程。

## 核心原则

### 一、离线优先，本地拥有数据（Offline-First, Local-First）

MVP 阶段不引入任何账号体系、后端服务与云同步。所有运动记录、训练数据仅存储在用户设备本地（SQLite）。
- 任何功能不得在联网失败时阻断核心流程（开始运动、记录轨迹、跟练计时必须 100% 离线可用）。
- 不为了"将来上云"而提前抽象网络层；云同步是 v3 的独立特性，届时单独立项。
- 用户数据属于用户：提供数据删除能力；不采集任何分析埋点上报。

### 二、核心链路可靠性高于一切（Reliability Over Features）

运动记录是用户用汗水产生的数据，**丢失一次记录比少一个功能严重得多**。
- 轨迹点必须边采集边持久化（增量写入本地存储），禁止只在内存中累积、结束时一次性保存。
- App 被切后台、来电、系统内存回收后，恢复时必须能重建进行中的运动状态。
- 任何新增功能不得增加记录链路的崩溃面；与记录冲突时，记录优先。

### 三、简单优先，克制抽象（Simplicity & YAGNI）

团队规模小（个人 + AI 协作），可读性优先于"优雅"。
- 能用一个文件说清的不拆三个；能用平铺状态的不引状态机库。
- 每个三方依赖必须有明确理由并在 plan 中注明；优先使用 Expo 官方生态（expo-location / expo-sqlite / expo-router）。
- 禁止为假想需求写配置化、插件化代码。

### 四、测试中核心，不求全覆盖（Test the Core）

- **必须有测试**：纯函数领域逻辑——距离计算（Haversine）、配速/速度换算、GPS 点滤波降噪、时间格式化、统计聚合。这些不依赖原生 API，用 Jest 单测覆盖。
- **不强求测试**：UI 组件快照、原生模块（定位、SQLite 驱动）——用真机手动验证清单代替，清单随 tasks.md 交付。
- 不追求覆盖率数字，追求"改坏核心计算时一定有测试报警"。

### 五、一套设计规范，原型即真相源（Design Consistency）

`design/` 目录下的高保真原型是 UI 实现的**唯一视觉基准**。
- 配色、字阶、圆角、间距以 `design/index.html` 底部的设计规范速查为准，不在代码中另造色值。
- 深色主题为唯一主题（MVP 不做浅色模式）。
- 实现与原型出现偏差时，默认以原型为准；确需调整先改原型再改代码。

## 技术约束

| 项 | 约束 | 理由 |
|---|---|---|
| 框架 | React Native + Expo（TypeScript 严格模式） | 一套代码双端；生态与 AI 协作友好 |
| 地图 | 高德地图（国内合规，GCJ-02 坐标系） | 国内上架与定位偏移合规要求 |
| 定位 | expo-location 后台定位 | 官方维护，Expo Go/Dev Build 兼容 |
| 存储 | expo-sqlite | 轨迹点数据量大，关系型查询更合适 |
| 状态 | zustand | 轻量，无样板代码 |
| 导航 | expo-router（文件路由） | 官方推荐，深链天然支持 |
| 视频 | MVP 不引入；动作演示用静态示意图 | 规避版权风险与包体积 |

## 性能标准

- 跑步记录页帧率保持流畅（地图 + 实时数据刷新不得明显卡顿）。
- 定位采样间隔 3–5 秒 + 位移阈值过滤，兼顾精度与电量；连续记录 1 小时不得导致设备明显发烫。
- 冷启动到首页可交互 < 3 秒（中端 Android 机）。
- 历史记录列表 100 条内滚动流畅。

## 开发工作流

1. **SDD 流程**：所有特性走 spec-kit 七阶段（constitution → specify → clarify → plan → tasks → analyze → implement），文档中文撰写。
2. **分支模型**：每个特性一个分支（`NNN-feature-name`），完成后合并回 main。
3. **质量门禁**：合并前必须——`tsc --noEmit` 零错误、核心逻辑单测全绿、真机（iPhone）走完该特性手动验证清单。
4. **文档同步**：实现与 plan 出现偏差时，先更新 plan 再继续编码；tasks.md 实时勾选进度。

## 治理

- 本章程优先于个人偏好与临时决定；修订需记录修订原因与日期，并同步检查受影响的 spec/plan。
- 每次新特性 plan 评审时，显式对照本章程逐条自查。
