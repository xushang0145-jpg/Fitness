# 功能规格：跟练课程

**Feature Branch**: `002-follow-along-courses`

**Created**: 2026-09-02

**Status**: Implemented

**Input**: 用户描述："健身 App 下一阶段核心特性：跟练课程，让用户在不依赖 GPS 的场景下按结构化课程完成训练。"

## 用户场景与测试 *(mandatory)*

### 用户故事 1 - 完成一次完整跟练 (Priority: P1)

用户想在家里或办公室利用碎片时间做一套结构化训练。打开 App 切换到「跟练」Tab，看到分类清晰的课程卡片（燃脂、塑形、拉伸等）。选择一门符合当前时间和难度的课程，进入详情页预览动作列表、预计时长、难度后点击「开始跟练」。课程按动作顺序逐个引导：计时类动作显示倒计时并播放静态示意图，计数类动作让用户每完成一次点击一次计数。遇到需要休息时自动进入组间休息倒计时。全部动作完成后进入完成页，系统把本次训练记录保存到本地，并计入个人统计。

**为什么是这个优先级**: 这是跟练课程模块的核心价值。从发现课程到完成记录的完整闭环一旦跑通，App 就拥有了 GPS 运动之外第二条独立的内容消费链路，能覆盖室内、碎片时间等场景。

**独立测试**: 选择任意一门内置课程，从列表 → 详情 → 开始 → 执行所有动作 → 完成，验证记录出现在「跟练历史」且「我的」页训练次数 +1。

**验收场景**:

1. **Given** 用户在首页且已切换至「跟练」Tab，**When** 页面加载完成，**Then** 展示课程分类筛选项（全部 / 燃脂 / 塑形 / 拉伸 / 全身）和课程卡片列表
2. **Given** 用户在课程列表页，**When** 点击「燃脂」分类，**Then** 列表只显示燃脂类课程；点击「全部」则恢复显示全部课程
3. **Given** 用户在课程列表页，**When** 点击任意课程卡片，**Then** 进入课程详情页，展示封面、标题、预计时长、难度、器械、动作列表与每个动作的简要说明
4. **Given** 用户在课程详情页，**When** 点击「开始跟练」，**Then** 进入跟练执行页，从第一个动作开始引导
5. **Given** 用户在跟练执行页且当前为计时动作，**When** 倒计时走到 0，**Then** 自动标记该动作完成并进入下一个动作或组间休息
6. **Given** 用户在跟练执行页且当前为计数动作，**When** 用户点击「+1」达到目标次数，**Then** 标记该动作完成并进入下一个动作或组间休息
7. **Given** 用户在跟练执行页，**When** 点击「结束跟练」，**Then** 弹出确认框；确认后保存已完成的动作记录，进入完成页展示本次时长、完成动作数、消耗卡路里
8. **Given** 用户完成课程全部动作，**When** 最后一个动作结束，**Then** 自动进入完成页并生成一条 course_record 计入统计

---

### 用户故事 2 - 查看动作要领与常见错误 (Priority: P2)

用户在开始跟练前想确认某个动作的标准做法，避免受伤。在课程详情页点击某个动作，进入动作详情页，看到大图示意图、步骤分解、呼吸节奏、常见错误提示。也可以在这里直接将该动作加入收藏（本地存储，不依赖后台）。

**为什么是这个优先级**: 帮助用户正确、安全地完成训练，提升内容可信度与复用率；但不影响 P1 的核心闭环。

**独立测试**: 进入任意课程详情，点击一个动作，验证示意图、步骤、常见错误、器械要求均正确展示。

**验收场景**:

1. **Given** 用户在课程详情页，**When** 点击动作列表中某一项，**Then** 进入动作详情页，展示该动作大图、步骤分解、常见错误
2. **Given** 用户在动作详情页，**When** 点击收藏图标，**Then** 图标变为已收藏状态，且该动作出现在「我的」收藏列表（若本期实现收藏）
3. **Given** 用户在动作详情页，**When** 点击「开始本课程」，**Then** 返回课程详情页或直接拉起课程执行页

---

### 用户故事 3 - 查看跟练历史与统计 (Priority: P3)

用户想回顾自己跟练过的课程和累计训练情况。在「我的」页或独立的「跟练历史」入口中，按时间倒序查看每次跟练的摘要（课程名、完成时间、时长、消耗、完成动作数 / 总动作数）。这些记录与运动记录一起参与总训练次数、总时长、总消耗的统计。

**为什么是这个优先级**: 历史与统计是激励层功能，依赖 P1 产生数据；P3 最后交付，且与 001-workout-tracking 的统计能力打通。

**独立测试**: 完成 2 门不同课程后，进入「我的」页与「跟练历史」页，验证列表展示正确，累计训练次数 = 运动次数 + 跟练次数。

**验收场景**:

1. **Given** 用户存在多条跟练记录，**When** 进入「我的」页，**Then** 「累计训练次数」同时统计运动记录与跟练记录；「累计消耗」为两者消耗之和
2. **Given** 用户存在多条跟练记录，**When** 进入「跟练历史」页，**Then** 按完成时间倒序展示列表，每条显示课程名、日期、时长、消耗、完成度
3. **Given** 用户在跟练历史列表，**When** 点击某条记录，**Then** 进入单次跟练详情页，展示课程信息、完成动作明细与总览
4. **Given** 用户只完成了一部分动作就结束，**When** 查看该次记录详情，**Then** 已完成的动作标记为完成，其余标记为未完成 / 跳过，完成度 = 已完成数 / 总动作数

---

### 边界情况

- **课程执行中切后台 / 锁屏**: 跟练计时暂停；用户回到 App 后提示「已暂停，点击继续」，不自动流逝时间，避免计数错误
- **用户提前结束**: 已完成的动作计入记录，未完成的动作不计入；完成度按实际完成数计算
- **动作跳过**: 用户可以选择跳过某个动作，跳过的动作不计入完成数但记录为 skipped，不消耗卡路里
- **计数动作误触 +1**: 支持 -1 回退或撤销本次点击；不允许负值
- **最后一个动作完成**: 自动进入完成页，无需用户再点下一步
- **无课程记录的新用户**: 「我的」页跟练相关统计展示 0，「跟练历史」展示空状态引导
- **课程数据损坏 / 缺失**: 启动时校验内置课程 JSON，缺失必填字段的课程不显示，错误记录到控制台，不阻塞其他课程
- **暂停期间屏幕常亮**: 跟练执行页保持屏幕常亮（MVP 用系统设置提示，不强制锁屏策略）

## 需求 *(mandatory)*

### 功能需求

- **FR-001**: 系统 MUST 在「跟练」Tab 展示内置课程列表，支持按分类筛选：全部 / 燃脂 / 塑形 / 拉伸 / 全身
- **FR-002**: 系统 MUST 为每个课程展示：封面图、标题、副标题、预计时长、难度（初 / 中 / 高）、目标肌群、器械要求、估算消耗
- **FR-003**: 系统 MUST 提供课程详情页，展示课程简介、动作列表（顺序、名称、类型、目标次数 / 时长 / 组间休息）与总预计时长
- **FR-004**: 用户 MUST 能在课程详情页点击单个动作进入动作详情页，查看大图示意图、步骤分解、呼吸提示、常见错误
- **FR-005**: 用户 MUST 能从课程详情页点击「开始跟练」进入课程执行页
- **FR-006**: 课程执行页 MUST 按动作顺序逐步引导，当前动作高亮展示：名称、示意图、步骤提示、计数或计时控件
- **FR-007**: 系统 MUST 支持两种动作类型：
  - `timer`: 持续 N 秒（如平板支撑 30s），倒计时到 0 自动进入下一步
  - `counter`: 完成 N 次（如俯卧撑 12 次），用户手动点击 +1，达到目标后进入下一步
- **FR-008**: 系统 MUST 在每组动作之间插入组间休息倒计时（rest 类型），倒计时到 0 自动进入下一动作；用户可点击「跳过休息」
- **FR-009**: 用户 MUST 能在课程执行页暂停、继续、跳过当前动作、提前结束课程
- **FR-010**: 系统 MUST 记录每个动作的实际完成情况：实际时长 / 实际次数、状态（done / skipped / pending）
- **FR-011**: 课程结束时系统 MUST 生成完成页，展示：课程名、总时长、完成动作数 / 总动作数、估算消耗、完成度圆环
- **FR-012**: 系统 MUST 把完成的课程保存为 `course_record`，存入本地 SQLite，并计入统计（总训练次数、总时长、总消耗）
- **FR-013**: 系统 MUST 提供「跟练历史」列表页，按时间倒序展示 course_record 摘要
- **FR-014**: 系统 MUST 在「我的」页累计统计中同时计入运动记录与跟练记录（训练次数、时长、消耗），距离只来自运动记录
- **FR-015**: 所有内置课程数据 MUST 以静态 JSON / TypeScript 配置内置到 App，MVP 不引入后台下载
- **FR-016**: 动作演示 MUST 使用静态示意图 + 文字说明，MVP 不引入视频（章程约束）
- **FR-017**: 课程执行全流程 MUST 100% 离线可用，不依赖网络

### 关键实体 *(涉及数据)*

- **课程 (Course)**: 一次结构化训练方案。属性：唯一 id、标题、副标题、分类、难度、预计时长（秒）、估算卡路里、器械、封面图、描述、动作列表（有序）
- **课程动作 (CourseAction)**: 课程内的单个步骤。属性：id、所属课程、顺序、名称、类型（timer / counter / rest）、目标时长 / 次数、组数、组间休息时长、示意图、步骤说明、常见错误、呼吸提示
- **跟练记录 (CourseRecord)**: 用户完成或提前结束一次课程的记录。属性：id、课程 id、开始时间、结束时间、总时长（秒）、完成动作数、总动作数、估算消耗、状态（active / done）
- **跟练记录步骤 (CourseRecordStep)**: 一次跟练中每个动作的实际执行情况。属性：id、记录 id、动作 id、顺序、计划时长 / 次数、实际时长 / 次数、状态（pending / done / skipped）

## 成功标准 *(mandatory)*

### 可衡量结果

- **SC-001**: 用户从进入「跟练」Tab 到点击「开始跟练」，操作 ≤ 3 步、耗时 < 10 秒
- **SC-002**: 内置课程在首次安装、无网络时即可完整加载并展示列表与详情
- **SC-003**: 计时动作倒计时误差 < 1 秒；计数动作次数统计零误差
- **SC-004**: 课程完成后 1 秒内生成 `course_record` 并在「跟练历史」可见
- **SC-005**: 「我的」页累计训练次数 = 运动记录次数 + 跟练记录次数，误差为 0
- **SC-006**: 核心领域逻辑（进度、卡路里、完成度、格式化）单元测试全部通过

## 澄清记录

### Q1: 跟练课程与动作库的关系？
**背景**: 早期原型 05~07 呈现的是「动作库 + 单个动作跟练」，但 issue 要求的是结构化课程。
**决定**: MVP 采用「课程」为唯一入口，课程由有序动作组成；动作详情页作为课程详情页的下钻，不提供独立动作库浏览。后续可考虑把动作库作为课程拆分的副产品。

### Q2: 卡路里如何估算？
**背景**: 课程无 GPS 距离，需要与 001 的 MET 公式保持一致口径。
**决定**: 课程级估算使用 MET × 体重(kg) × 课程时长(h)。课程元数据内置平均 MET；单个 timer 动作的消耗按其在课程时长中的比例分摊，counter 动作按目标次数与标准代谢当量估算。完成度 < 100% 时按实际完成动作比例折算总消耗。

### Q3: 用户中途退出或切后台如何处理？
**背景**: 影响计时准确性与用户体验。
**决定**: 课程执行页切后台或锁屏时自动暂停计时；返回后需用户手动点击「继续」恢复。提前结束课程时保存已完成的动作。不支持像运动记录那样的后台持续计时。

### Q4: 跟练记录如何与运动记录「共用统计逻辑」？
**背景**: issue 明确要求共用统计。
**决定**: 新增 `course_record` 表，与 `workout` 表并列。`domain/stats.ts` 扩展为接受 `(workouts, courseRecords, now)`，分别计算训练次数、总时长、总消耗、近 7 天活跃天；距离统计仅来自 workout。UI 层在「我的」页合并展示。

## 假设

- 用户主要在室内或固定场景使用跟练功能，不依赖 GPS
- 内置课程数量为 4 门 MVP 课程，以静态 JSON / TypeScript 文件形式内置
- 所有动作示意图使用 AI 生成占位图或本地静态资源，MVP 不做动态下载
- 不支持用户自定义课程、社区课程、后台下载更新
- 用户体重来自 001 的 settings 表，用于卡路里估算
- 语音播报、视频、背景音乐均不在本期范围（v2 候选）
