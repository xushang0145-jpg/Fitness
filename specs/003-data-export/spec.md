# 功能规格：运动数据导出（GPX / CSV）

**Feature Branch**: `003-data-export`

**Created**: 2026-09-02

**Status**: Implemented（待真机验证与合并收尾）

**Input**: 用户描述：运动记录累计后，用户需要一种方式把数据从设备中导出，用于备份或第三方分析。

## 用户场景与测试 *(mandatory)*

### 用户故事 1 - 导出全部轨迹为 GPX（Priority: P1）

用户积累了多次跑步、骑行或步行记录，希望把这些轨迹一次性导出为一个标准 GPX 文件，用于备份或导入 Keep / Strava / 高德等第三方应用。

**为什么是这个优先级**: 章程原则一明确规定「用户数据属于用户」。导出能力是实现数据可携带性的最小必要功能，必须在 MVP 阶段提供。

**独立测试**: 预先制造 3 条不同运动类型的记录（含轨迹点），进入「我的 → 设置 → 数据导出」，点击「导出 GPX 轨迹」，验证生成的 `.gpx` 文件能被第三方应用识别，且轨迹点与原始记录一致。

**验收场景**:

1. **Given** 用户在数据导出页，**When** 点击「导出 GPX 轨迹」，**Then** 系统生成单个 `.gpx` 文件，包含所有已完成运动，每条运动作为一个 `<trk>`，轨迹点按时间顺序写入 `<trkseg>`
2. **Given** 生成的 GPX 文件，**When** 分享到微信 / Files / 邮件，**Then** 文件扩展名为 `.gpx`，内容为合法 XML，头部声明 GPX 1.1 与 UTF-8 编码
3. **Given** 某条运动记录无任何轨迹点（如被放弃的极短记录），**When** 导出 GPX，**Then** 该记录仍作为 `<trk>` 出现，包含名称与时间元数据，`<trkseg>` 可为空
4. **Given** 将 GPX 导入 Keep / Strava / 高德，**When** 地图渲染轨迹，**Then** 路线可识别，且在中国境内与原始地图显示偏差在可接受范围

---

### 用户故事 2 - 导出统计汇总为 CSV（Priority: P1）

用户想用 Excel 或 Numbers 快速查看自己的运动历史汇总，做月度/年度统计，因此需要一份包含每次运动关键指标的 CSV。

**为什么是这个优先级**: 与故事 1 同等重要，满足用户以表格形式分析数据的诉求；实现成本低，可与 GPX 共用同一查询入口。

**独立测试**: 预先制造多条跨日期记录，导出 CSV 后在本机用电子表格应用打开，验证表头、行数、数值均正确。

**验收场景**:

1. **Given** 用户在数据导出页，**When** 点击「导出 CSV 汇总」，**Then** 系统生成 `.csv` 文件，表头固定为：`日期,类型,距离(km),时长(s),卡路里(kcal),平均配速/速度`
2. **Given** CSV 文件在 Excel / Numbers 中打开，**When** 查看中文表头，**Then** 无乱码（文件带 UTF-8 BOM）
3. **Given** 用户没有任何运动记录，**When** 导出 CSV，**Then** 文件仅包含表头行，无崩溃
4. **Given** 用户有多条记录，**When** 导出 CSV，**Then** 行按运动开始时间倒序排列，`距离` 显示两位小数，`卡路里` 显示整数或一位小数，与数据库原始值一致

---

### 用户故事 3 - 通过系统分享面板保存或发送文件（Priority: P1）

导出后的文件需要离开 App，保存到本地文件系统或发送给他人。用户希望通过系统原生分享面板完成，而不是 App 内自建文件管理。

**为什么是这个优先级**: 分享面板是 iOS / Android 标准交互，能一次性覆盖 Files、微信、邮件、AirDrop 等目标，避免为每个平台单独集成。

**独立测试**: 导出 GPX 与 CSV 后，分别分享到 iOS Files 应用，确认文件可被保存并再次打开。

**验收场景**:

1. **Given** 文件已生成，**When** 用户点击「分享」或导出按钮，**Then** 系统分享面板（UIActivityViewController / Sharesheet）弹出
2. **Given** 分享面板已打开，**When** 用户选择「保存到文件」，**Then** 文件成功保存到用户指定的 Files 位置
3. **Given** 分享面板已打开，**When** 用户选择微信 / 邮件，**Then** 文件作为附件发送（受目标应用自身大小/格式限制）
4. **Given** 用户在分享面板中取消操作，**When** 返回 App，**Then** App 仍停留在导出页，无崩溃、无异常提示

---

### 边界情况

- **空态**: 用户无运动记录时，导出页仍需可导出（生成仅含元数据或表头的文件），并显示友好说明
- **大数据量**: 连续 100 条记录、单条平均 500 个轨迹点时，导出生成时间应 < 2 秒，不阻塞 UI
- **文件重名**: 文件名自动附加时间戳，避免覆盖旧文件
- **分享取消**: 用户取消分享不视为错误，无需提示
- **无分享目标**: 系统未安装任何可接收文件的应用极罕见，若发生则展示「暂无可用的分享目标」提示
- **坐标兼容性**: 数据库使用 GCJ-02，GPX 国际标准使用 WGS-84，需做转换；CSV 只展示统计值，无需坐标

## 需求 *(mandatory)*

### 功能需求

- **FR-001**: 系统 MUST 在「我的」页面 →「设置与目标」中提供「数据导出」入口
- **FR-002**: 用户 MUST 能将所有已完成运动记录导出为单一 `.gpx` 文件
- **FR-003**: GPX 文件 MUST 符合 GPX 1.1 格式：根元素 `<gpx>`，每个运动为 `<trk>`，包含 `<name>`、`<time>`、`<trkseg>`，轨迹点为 `<trkpt lat="..." lon="...">`，可包含 `<ele>` 与 `<time>`
- **FR-004**: GPX 中的坐标 MUST 为 WGS-84；系统 MUST 将数据库中 GCJ-02 坐标反向转换为 WGS-84 后写入
- **FR-005**: 系统 MUST 能导出 CSV 汇总，固定列为：`日期,类型,距离(km),时长(s),卡路里(kcal),平均配速/速度`
- **FR-006**: CSV 文件 MUST 使用 UTF-8 编码并带 BOM，以便 Excel / Numbers 正确识别中文字符
- **FR-007**: 导出文件名 MUST 包含应用名、格式与生成时间，例如 `FitApp_Records_20260902_154030.gpx`、`FitApp_Summary_20260902_154030.csv`
- **FR-008**: 系统 MUST 在文件生成后唤起系统原生分享面板，由用户选择保存或发送目标
- **FR-009**: 导出页 MUST 展示功能说明，让用户清楚 GPX 与 CSV 分别包含什么数据
- **FR-010**: 导出流程 MUST 完全离线执行，不得上传任何数据到网络

### 关键实体 *(涉及数据)*

- **运动记录 (Workout)**: 沿用 `001-workout-tracking` 定义。导出时只取 `status='done'` 的记录；字段包括 type、startTime、endTime、durationS、distanceM、avgPaceS、avgSpeedKmh、calories
- **轨迹点 (TrackPoint)**: 沿用 `001-workout-tracking` 定义。导出 GPX 时使用 lat、lng、altitude、timestamp
- **导出任务 (ExportJob)**: 临时状态（非持久化）。属性：format（'gpx' | 'csv'）、fileUri、status（'idle' | 'generating' | 'ready' | 'error'）、errorMessage

## 澄清记录

### Q1: GPX 应该使用哪种坐标系？
**背景**: 数据库存储的是 GCJ-02（高德坐标系），而 GPX 国际标准使用 WGS-84。国内应用（Keep / 高德）可能对 GCJ-02 更友好，国际应用（Strava）严格要求 WGS-84。
**决定**: 导出 GPX 使用 WGS-84，以符合 GPX 1.1 规范并保证 Strava 兼容。在 `domain/geo.ts` 中补充 `gcj02ToWgs84()` 反向转换函数，并对转换函数做 roundtrip 单元测试。

### Q2: 一次性导出全部记录还是按条/按日期范围导出？
**背景**: 按日期范围或单条导出体验更灵活，但会增加 UI 复杂度。
**决定**: MVP 为「一次性导出全部已完成记录」。日期范围、单条导出、选择性导出列入 v2 候选。

### Q3: CSV 中跑步/步行与骑行的速度口径如何统一？
**背景**: 跑步/步行统计习惯用「配速（分钟/公里）」，骑行习惯用「速度（公里/小时）」。
**决定**: 单列展示为「平均配速/速度」，内容根据运动类型动态：跑步/步行显示 `m'ss"/km`，骑行显示 `xx.x km/h`。并在导出页用文案说明。

## 假设

- `001-workout-tracking` 已完成并合并到 `main`，数据库表结构与 `data-model.md` 一致
- 用户授予了必要的文件/分享相关系统权限；`expo-sharing` 本身不需要额外 Info.plist 权限声明
- 第三方应用对 `.gpx` / `.csv` 的接受能力不在本 App 控制范围内；本功能只需正确生成文件并唤起系统分享
- 导出过程为只读，不修改、不删除任何原始运动记录
- 海拔数据可能缺失，GPX 中 `<ele>` 可选；缺失时不写该元素
